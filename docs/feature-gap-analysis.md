# PawBites 功能实现差距分析

> **实施进展（2026-11-05）**：第二、三、四节全部差距已实现——① 商品详情弹窗 + 我的订单抽屉（含取消订单）；② 日志管理整链路（V5 迁移 + `/api/logs` 6 接口 + admin.html/admin.js）；③ 个人中心抽屉 + 商品加载更多；④ 收藏 + 优惠券整链路（V6 迁移 + `/api/favorites`、`/api/coupons` + 注册/订阅发券 + 下单核销/取消返还 + 购物车选券 UI）。
> 生效前提：需对数据库手工执行 V5/V6 两个迁移脚本（当前 `application.yml` 中 flyway 为关闭状态），并重启后端。

> 分析基准：`index.html` + `script.js`（C 端商城页）、`docs/ui-requie.md` / `docs/ui-spec.md`（日志管理页需求）、后端 9 个 Controller、V1–V4 数据库迁移（14 张表）、本地运行中的后端（`/api/health` 探测通过）。

## 三、需求文档已明确、前后端均未实现的功能（缺整条链路）

### 日志管理页面（`docs/ui-requie.md`、`docs/ui-spec.md`）

后台管理列表页：新增、编辑、删除、发布状态 Switch、标题模糊搜索、分页（10 条/页）、跳页、点击量展示。

| 层 | 现状 |
|----|------|
| 前端 | ❌ 页面完全不存在（仓库中无 admin 页面 HTML/JS） |
| 后端 | ❌ 6 个接口全部缺失：`GET /api/logs`（分页+关键字）、`POST /api/logs`、`PUT /api/logs/{id}`、`PUT /api/logs/{id}/status`、`DELETE /api/logs/{id}`、`GET /api/logs/{id}`（控制器目录中无 LogsController，运行中服务探测该路由不可用） |
| 数据库 | ❌ 14 张表中无 logs/notice 表，需新增 V5 迁移（含 title、type、content、publish_status、view_count、create_time 等字段及注释） |

规格中还有 9 个待产品确认问题（交互形式、物理/软删除、点击量口径等），见 `docs/ui-spec.md` §7。

## 四、页面 UI 已承诺、但无任何接口支撑的功能

| # | 页面元素 | 位置 | 差距 |
|---|---------|------|------|
| 1 | 「新人优惠」登录权益 | 登录页权益条 | 无优惠券表/接口；订阅接口仅回执文案「新人券稍后发送」，券的发放与核销链路缺失 |
| 2 | 「收藏商品」登录权益 | 登录页权益条 | 无收藏表、无接口、无 UI |
| 3 | 「订单同步」登录权益 | 登录页权益条 | 后端有订单接口，但前端无账户中心承载 |
| 4 | 「今日热卖 鸡肉冻干 2件85折」角标 | 首页 Hero | 静态营销文案，无促销/折扣接口 |
| 5 | 账户按钮 | 顶栏 | 仅能退出登录，无个人中心（资料、改密、订单聚合入口） |
| 6 | 客服 / 破损包赔 / 满包邮说明 | 页脚 | 静态占位（可暂不接口化，属内容维护问题） |

## 五、建议实施顺序

1. **商品详情 + 我的订单（列表/详情/取消）**：后端接口齐备，只差前端，投入最小、闭环最直接。
2. **日志管理页**：需求文档最完整的一条新链路，需 DB 迁移 + 后端 6 接口 + 前端管理页，先落 §7 的 9 个待确认问题再动工。
3. **收藏 / 优惠券**：页面已对外承诺的权益，需要补 表 + 接口 + UI 的完整设计。
4. 商品分页 UI、个人中心：体验补全项。
