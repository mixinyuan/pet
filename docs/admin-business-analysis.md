# PawBites 后台管理系统 · 业务梳理与需求规格

> 版本：v0.1（2026-11-05，基于 dev 分支代码现状梳理）
> 配套交付：可交互 HTML 原型（见会话内可视化卡片，或仓库外原型文件）
> 阅读对象：产品/开发自己人。目的：把「做后台」这件事从一句话拆成可开发的模块清单。

---

## 一、为什么做 / 做什么

现状：C 端商城（`index.html`）业务已闭环（浏览→购物车→下单→取消），但**商品、场景套餐、订单、用户等所有数据只能靠改数据库维护**。管理端唯一现成的链路是「日志管理」（`admin.html` + `/api/logs`）。

本期目标：建设统一的后台管理系统，让管理员可以：

| # | 能力 | 深度（已与负责人确认） |
|---|------|----------------------|
| 1 | 维护商品 | 完整 CRUD + 上下架 + 分类/标签维护 |
| 2 | 维护场景套餐 | 完整 CRUD + 商品明细子表 + 上下架 |
| 3 | 查看订单 | 只读列表/详情 + **管理员取消**（不做发货/支付流转） |
| 4 | 查看用户 | 只读列表/详情 + **禁用/启用账号**（不编辑资料/不重置密码） |
| 5 | 评价管理 | 列表 + 隐藏/显示 |
| 6 | 优惠券模板管理 | 模板 CRUD + 停用（发放仍走注册/订阅自动触发） |
| 7 | 数据看板 | 首页只读聚合统计 |
| 8 | 日志管理 | 整合现有 admin.html 能力，纳入统一导航 |

## 二、现状盘点（设计依据）

| 领域 | 现状 | 对后台设计的影响 |
|------|------|----------------|
| 权限 | `users` 表无 role 字段；JWT 固定授予 `ROLE_USER`；`/api/logs/**` 仅要求登录（**任何注册用户都能改日志**） | 必须先引入管理员角色，否则后台接口裸奔 |
| 商品 | `product` 表含 sku/name/pet_type/flavor/price/rating/stock/status/image_url/description；多分类(product_category_rel)+多标签(product_tag_rel)；C 端强制只查 ACTIVE | 无任何管理接口；「删除」应走已有 `deleted` 逻辑删除字段 |
| 套餐 | `bundle`(现价/原价/折扣文案/排序) + `bundle_item`(商品+数量) 明细 | 编辑表单需要「明细子表编辑器」这一新形态 |
| 订单 | 仅 CREATED/CANCELLED 两态；下单即扣库存、取消回补库存+退券；订单条目为**快照**（改名改价不影响历史订单） | 详情页只能展示快照字段；无收货人/地址/支付信息可展示 |
| 用户 | username/email 唯一，status(ACTIVE/INACTIVE)，BCrypt 密码 | 禁用用户后，已签发的 JWT（默认 168h）仍有效 → 见 §九 Q3 |
| 评价 | review 表已有 status(ACTIVE 展示/INACTIVE 隐藏) 字段 | 只需补管理接口，表结构不动 |
| 优惠券 | coupon(模板，仅固定金额) + user_coupon(实例，注册/订阅自动发放) | 模板管理新增；停用模板不影响已发实例（建议） |
| 图片 | 无上传能力，全站 Unsplash 外链 URL | 第一版：URL 输入框 + 实时预览；上传列为二期 |
| 风格基准 | admin.html：顶栏+白卡片+表格+分页+弹窗+行内 Switch+toast，主色 #409EFF | 新后台沿用该交互语言，升级为「侧边栏 + 多模块」框架 |

## 三、角色与权限

### 3.1 角色定义

| 角色 | 来源 | 能力 |
|------|------|------|
| 管理员 ADMIN | `users.role = 'ADMIN'`（V7 迁移加列，存量管理员用 SQL 手工指定） | 访问后台全部模块 |
| 普通用户 USER | 默认值 | 仅 C 端；访问 `/api/admin/**` 返回 403 |

### 3.2 鉴权方案（建议）

1. `users` 表加 `role VARCHAR(16) DEFAULT 'USER'`（V7 迁移）。
2. `JwtService` 签发时带 role；`JwtAuthenticationFilter` 解析出 `ROLE_ADMIN`/`ROLE_USER`。
3. 后端新增管理接口统一收敛到 **`/api/admin/**`** 前缀，`SecurityConfig` 配置 `hasRole('ADMIN')`——顺带修复 `/api/logs` 的越权问题（迁移到 `/api/admin/logs`，旧路径保留兼容或下线，见 Q8）。
4. 后台前端登录页复用 `POST /api/auth/login`，校验返回的 `role === 'ADMIN'`，否则提示无权访问。
5. 管理员账号日常创建走 SQL / 种子数据（不开放注册管理员），见 Q1。

### 3.3 后台登录与门禁（沿用 admin.html 模式）

- 复用 localStorage `pawbites-auth` 登录态；未登录/非管理员/token 失效 → 全屏「登录门」。
- 任何 401 清登录态回登录门；403 提示「无管理员权限」。

## 四、信息架构与导航

```
PawBites 管理后台
├─ 登录门（账号密码，仅 ADMIN）
└─ 主框架：左侧固定导航 + 顶栏（当前账号 / 返回商城 / 退出）

    ├─ 2 商品管理        /admin/products
    │    ├─ 商品列表（含上下架 Switch）
    │    ├─ 分类管理（子标签页）
```

## 五、模块业务梳理

> 每个模块按「列表列定义 → 筛选/搜索 → 操作 → 表单字段 → 业务规则」梳理。
> 列定义格式：列名(字段) [宽度建议]。

### 5.1 数据看板 `/admin`

**定位**：管理员打开后台的第一眼，回答「今天生意怎么样、有没有要处理的异常」。

| 区块 | 内容 | 数据来源（建议新增聚合接口） |
|------|------|------|
| 统计卡片 ×4 | 今日新增订单 / 今日销售额 / 注册用户总数 / 库存预警商品数 | `GET /api/admin/dashboard/summary` |
| 待处理事项 | 待处理：无（订单无待发货态）→ 展示「近 7 日取消订单」快捷入口 | 同上 |
| 最近订单 | 最近 10 笔订单简表（单号/用户/金额/状态/时间），点击跳订单管理并定位 | `GET /api/admin/dashboard/recent-orders` |
| 热销 TOP5 | 按订单条目销量聚合的商品排行（名称/销量/销售额） | `GET /api/admin/dashboard/top-products` |
| 库存预警 | stock < 20 的商品列表（名称/库存/快捷「去补库存」→ 打开商品编辑弹窗） | `GET /api/admin/dashboard/low-stock` |

规则：看板纯只读；所有卡片/列表点击均跳转到对应模块；无数据时显示占位文案。

### 5.2 商品管理 `/admin/products`

**定位**：维护商品主数据。这是使用频率最高的模块。

**列表列**：

| 列 | 字段 | 说明 |
|----|------|------|
| 商品 | imageUrl + name | 40px 缩略图 + 名称（单行省略）+ SKU 小字 |
| 分类 | categories | 标签样式，最多显示 2 个 + `+N` |
| 标签 | tags | 标签样式，最多显示 2 个 + `+N` |
| 适用宠物 | petType | 猫咪适用/狗狗适用/猫狗通用 |
| 价格 | price | ¥xx.00 |
| 库存 | stock | <20 红色高亮（预警线可在 Q6 调整） |
| 评分 | rating | ★ x.x |
| 上架状态 | status | 行内 Switch：ACTIVE/INACTIVE，关闭后 C 端立即不可见 |
| 操作 | — | 编辑 / 删除 |

**筛选/搜索**：关键字（名称/SKU/口味模糊）、分类下拉、状态（全部/上架/下架）。
**分页**：10 条/页，与日志管理同款分页组件。

**操作规则**：

| 操作 | 规则 |
|------|------|
| 新增 | 弹窗表单见下；SKU 全局唯一，重复时表单报错 |
| 编辑 | 同表单；改名/改价**不影响历史订单**（订单是快照） |
| 上下架 | Switch 乐观更新；下架商品保留购物车/收藏引用，C 端展示「已下架」占位 |
| 删除 | 二次确认弹窗；**逻辑删除**（deleted=1）；已被订单/套餐引用的商品删除前需提示「该商品存在于 N 个套餐中」（见 Q2） |

**商品表单字段**：

| 字段 | 必填 | 校验 | 说明 |
|------|------|------|------|
| SKU | ✅ | ≤64 字符，全局唯一 | 建议格式 PB-XXX-XXX，输入时自动大写 |
| 商品名称 | ✅ | ≤100 字符 | |
| 适用宠物 | ✅ | 单选 | 猫咪适用/狗狗适用/猫狗通用 |
| 口味 | ✅ | ≤50 字符 | 如「鸡胸肉」「牛肉南瓜」 |
| 价格 | ✅ | > 0，两位小数 | |
| 库存 | ✅ | ≥ 0 整数 | |
| 评分 | ❌ | 0–5，一位小数 | 默认 5.0，人工维护（C 端评价暂不联动） |
| 图片 URL | ✅ | 合法 URL | 输入即预览缩略图；加载失败显示占位图并允许提交（见 Q5） |
| 分类 | ✅ | 多选 | 复选标签，至少 1 个（不含 all） |
| 标签 | ❌ | 多选 | 复选标签，来自标签管理 |
| 描述 | ❌ | ≤500 字符 | textarea |
| 上架状态 | ❌ | 默认上架 | Switch |

**分类管理（子标签页）**：列表（排序号/编码/名称/描述/状态Switch/操作），表单（编码*唯一小写、名称*、描述、排序号）。规则：编码被商品引用后不可改编码只可改名；`all` 为系统内置不可删。

**标签管理（子标签页）**：列表（名称/引用商品数/状态Switch/操作），表单（名称*唯一）。规则：删除前检查引用数，被引用则禁止删除并提示。

### 5.3 场景套餐管理 `/admin/bundles`

**定位**：维护「多商品打包组合」。核心差异点是**明细子表编辑器**。

**列表列**：排序号 / 套餐（名称+描述摘要）/ 折扣文案 / 现价 / 原价 / 明细（含 N 件商品，如「3 种 · 共 5 件」）/ 上架状态 Switch / 操作（编辑、删除）。

**筛选**：关键字（名称）、状态。分页 10 条/页。

**套餐表单**：

| 字段 | 必填 | 校验 | 说明 |
|------|------|------|------|
| 套餐名称 | ✅ | ≤100 | |
| 现价 | ✅ | > 0 | |
| 原价 | ✅ | ≥ 现价（否则表单报错「原价应不低于现价」） | 划线展示用 |
| 折扣文案 | ❌ | ≤20 字 | 如「省 18%」，留空则 C 端不显示角标 |
| 排序号 | ❌ | 整数，默认 0 | 越小越靠前 |
| 描述 | ❌ | ≤200 | |
| 商品明细 | ✅ | ≥ 1 行 | 子表编辑器，见下 |
| 上架状态 | ❌ | 默认上架 | |

**明细子表编辑器**（新交互形态）：

```
┌ 明细商品 ────────────────────────────── [+ 添加商品] ┐
│ 商品（下拉搜索，仅上架商品）  数量 [- 1 +]  小计   操作 │
│ 原切鸡肉冻干  ¥39.00        [2]       ¥78.00  [移除] │
│ 薄荷洁齿棒    ¥45.00        [1]       ¥45.00  [移除] │
├─────────────────────────────────────────────────────┤
│ 明细合计 ¥123.00   [一键填入明细合计为原价]            │
└─────────────────────────────────────────────────────┘
```

规则：同一商品不可重复添加（提示去重）；数量 1–99；行随删随加；「一键填入」把明细合计写进原价字段，方便算折扣；提交时后端整体替换 bundle_item（先删后插，事务内）。

**业务规则**：套餐与订单无关联（C 端暂不能直接购套餐，仅展示）→ 编辑套餐不影响任何历史数据；套餐内商品下架时，C 端套餐区展示该商品置灰（后端 VO 需补此标记，属于 C 端小改，列入接口缺口）。

### 5.4 订单管理 `/admin/orders`

**定位**：只读查阅 + 管理员兜底取消。**不做**支付/发货/完成流转（已确认）。

**列表列**：订单号(PB…，等宽字体) / 下单用户（昵称或「游客 guestId 后 8 位」）/ 商品件数 / 订单总额 / 优惠（¥-x 或 —）/ 状态（标签：已创建-蓝 / 已取消-灰）/ 下单时间 / 操作（详情、取消〔仅已创建〕）。

**筛选/搜索**：订单号精确搜索、用户名/昵称模糊、状态筛选（全部/已创建/已取消）、下单时间范围（起止日期，本系统首个时间范围查询）。

**订单详情弹窗**（或右侧抽屉）：

| 区块 | 内容 |
|------|------|
| 头部 | 订单号 + 状态标签 + 下单时间 |
| 用户信息 | 昵称 / 用户名 / 邮箱（游客单显示游客标识） |
| 商品快照列表 | 图 + 名称 + 单价(下单时) + 数量 + 小计 —— **全部为下单快照** |
| 金额汇总 | 商品合计 / 优惠券抵扣（含券名）/ 实付总额 |
| 优惠券 | 若用券：券名 + 面额 + 核销时间 |
| 取消信息 | 若已取消：取消时间（现有表无取消时间字段 → Q4） |

**管理员取消**：操作列「取消」→ 二次确认弹窗（红色警示：将回补库存并退还用户优惠券）→ 调用与 C 端同一取消逻辑（原子回补库存 + user_coupon 返还）。规则：仅 CREATED 可取消；取消不可逆。

### 5.5 用户管理 `/admin/users`

**定位**：只读查阅 + 禁用/启用。**不**提供编辑资料、重置密码（已确认）。

**列表列**：ID / 用户（头像字+昵称+用户名小字）/ 邮箱 / 订单数 / 消费金额 / 持券数（可用）/ 账号状态（Switch：正常/已禁用）/ 注册时间 / 操作（详情、禁用|启用）。

**筛选/搜索**：关键字（用户名/昵称/邮箱模糊）、状态（全部/正常/禁用）。

**用户详情抽屉**：

| 区块 | 内容 |
|------|------|
| 基本资料 | 头像字 / 昵称 / 用户名 / 邮箱 / 注册时间 / 状态 |
| 订单记录 | 该用户订单简表（复用订单列表列），点击跳订单管理 |
| 收藏 | 收藏商品数 + 最近收藏 5 个（缩略图） |
| 优惠券 | 持券列表（券名/状态/到期时间） |
| 订阅 | 邮箱订阅状态 |

**禁用/启用**：Switch 或按钮 + 二次确认（警示：禁用后该用户无法登录/下单；**已签发的 token 在过期前仍有效** → Q3 的两个解法）。规则：禁用不清数据、不删订单；被禁用用户调用需认证接口的行为由后端拒绝（现状 login 不查 status，需补：禁用用户登录报「账号已被禁用」）。

### 5.6 评价管理 `/admin/reviews`

**定位**：内容审核的最小闭环——只能隐藏/显示和编辑展示信息（评价由种子+后续 C 端展示，用户暂不能发布评价）。

**列表列**：评价人（buyer_name + pet_name·pet_breed）/ 内容（两行省略 + 查看全部）/ 关联商品（或「通用」）/ 评分(★) / 展示状态 Switch（展示/隐藏）/ 排序号 / 时间 / 操作（编辑、删除）。

**筛选**：关键字（内容/评价人）、状态、关联商品。

**编辑表单**：评价人姓名 / 宠物名 / 宠物品种 / 内容(textarea) / 头像 URL / 评分 / 关联商品(下拉，可空) / 排序号 / 展示状态。
**规则**：隐藏 = status INACTIVE，C 端立即不展示；删除走逻辑删除；排序号越小越靠前。

### 5.7 优惠券模板管理 `/admin/coupons`

**定位**：维护券模板。发放规则（注册/订阅自动发）本期不变，仅停用后不再自动发放。

**列表列**：券名称 / 类型（固定金额）/ 面额 / 使用门槛（满 ¥xx 可用）/ 有效期（领取后 N 天）/ 已发放 / 已使用 / 使用率 / 状态（启用/停用 Switch）/ 操作（编辑、删除）。

**表单**：名称* / 面额*（>0）/ 门槛*（≥0，0 表示无门槛，但当前注册发券为满 99）/ 有效天数*（默认 30）/ 备注。
**规则**：⚠️ **user_coupon 无金额快照列（V6 表结构事实）**——持券展示与核销时实时联查模板，因此**编辑模板的名称/面额/门槛会同步作用于存量持券用户**，管理端编辑表单必须展示醒目警示文案；若产品要求隔离，需后续迁移为 user_coupon 加快照列（二期）。停用模板（INACTIVE，V8 加列）= 新用户注册/订阅不再发这张券（发券逻辑已按 status=ACTIVE 过滤），存量持券照常展示与核销；删除需二次确认且已发放数 >0 时仅允许「停用」不允许删除（防审计断链）。
**使用率** = 已使用 / 已发放，列上直接展示百分比。

### 5.8 日志管理 `/admin/logs`（整合现有）

能力与现有 `admin.html` 完全一致：列表（序号/标题/类型/时间/发布状态 Switch/点击量/操作）、标题关键字搜索、10 条/页分页、新增/编辑弹窗、删除二次确认。
变化仅两处：① 挂进新后台统一侧边导航；② 接口迁移到 `/api/admin/logs` 并要求 ADMIN 角色（修复现状任何登录用户可改日志的越权问题）。

## 七、接口缺口清单

`POST /api/auth/login`（后台登录复用，响应需带 role）、`GET /api/auth/me`。

### 迁移（改权限）
`/api/logs/**` 6 个接口 → `/api/admin/logs/**`，要求 ROLE_ADMIN。

### 新建（统一挂 `/api/admin` 前缀，全部要求 ROLE_ADMIN）

| 模块 | 接口 | 备注 |
|------|------|------|

| 标签 | GET/POST/PUT/DELETE /admin/tags | 同上 |
